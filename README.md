# Anonymous artifact

Code and raw results for the submission *Budget-agnostic deployment of universal
adversarial perturbations* (double-blind review). Everything in this repository is
anonymized: no author names, affiliations, emails, or absolute paths.

The artifact supports two levels of reproduction:

* **Level 1 (seconds)** — regenerate every table and figure in the paper from the
  shipped per-run JSON. No GPU, no dataset download.
* **Level 2 (hours to days)** — re-run the experiments from scratch on ImageNet-1k
  and CIFAR-10.

Level 1 is the intended path for reviewers: it proves that every number in the
paper is a deterministic function of raw run outputs rather than a hand-typed
value.

---

## 1. Layout

```
.
├── paper/                 LaTeX source of the submission
│   ├── main.tex
│   ├── tables/            generated by analysis/make_tables.py
│   └── figs/              generated by analysis/make_figures.py
├── results_*/             raw per-run JSON (one file per surrogate × seed)
├── config.py              global configuration (paths, model list, budgets)
├── models.py              model zoo + pretrained checkpoints
├── evaluate.py            black-box / white-box fooling-rate evaluation
├── experiments.py         training loops for scale-up and per-budget arms
├── fewshot_uap_method.py  few-shot UAP objectives (incl. scale-up primitive)
├── sota_uap_baselines.py  UAP'17, FFA, SSA baselines
├── sota_modern.py         TSC-UAP and DM-UAP baselines
├── run_*.py               one driver per experiment family
├── analyze_*.py           per-experiment aggregation into summary JSON
├── make_tables.py         all LaTeX tables  <- Level 1 entry point
├── make_figures.py        all figures        <- Level 1 entry point
├── utils/                 data loaders and losses
├── third_party/
│   └── dmuap_vendor/      adapted reference implementation of the DM-UAP baseline
└── slurm_*.sh             cluster submission scripts (SLURM)
```

`results_*/` holds one JSON per `(surrogate, seed)`. Each JSON stores the
configuration actually used, the per-budget fooling rate of every method, the
saturation fraction, and wall-clock training time. Nothing is aggregated at this
level, so every aggregate in the paper can be recomputed and audited.

## 2. Level 1 — regenerate the paper's tables and figures

```bash
python -m venv .venv && source .venv/bin/activate
pip install numpy matplotlib          # nothing else is needed
python make_tables.py                 # writes paper/tables/*.tex
python make_figures.py                # writes paper/figs/*.pdf and *.png
```

Expected output: 11 table files and 3 figure pairs. **This was verified on the
shipped JSON: the 11 regenerated tables are byte-identical to the shipped ones**
(`md5sum paper/tables/*.tex` before and after the run shows no change). The PDFs
for the figures regenerate with identical content but different embedded
timestamps, so byte comparison of PDFs will differ; compare the PNGs or the plots
themselves.

Table-to-data mapping:

| Paper table | Generator | Data |
|---|---|---|
| `tab:main-imagenet` | `make_tables.py::t1_main_imagenet` | `results_fewshot_sota/` |
| `tab:clipdown` | `t2_clipdown` | `results_clipdown/` + `results_fewshot_sota/` |
| `tab:cifar` | `t3_cifar_control` | `results_cifar_control/` |
| `tab:cost` | `t4_cost` | `results_fewshot_sota/` (wall-clock fields) |
| `tab:permodel` | `t5_permodel` | `results_fewshot_sota/` |
| `tab:epsw`, `tab:bsweep`, `tab:ksweep`, `tab:l2` | `t6_suppl` | `results_suppl/` |
| `tab:svd` | `t7_svd` | `results_svduap/` |
| `tab:p2` | `t8_p2` | `results_p2/` |
| `fig:clipfrac`, `fig:deploy` | `make_figures.py` | `results_clipdown/` + `results_fewshot_sota/` |

Compiling the paper itself (optional): `cd paper && pdflatex main` twice, or upload
`paper/` to Overleaf. The build needs `acmart` (ACM `sigconf`) and nothing else.

## 3. Level 2 — re-run the experiments

### 3.1 Environment

```bash
pip install -r requirements.txt
```

Tested with Python 3.9, PyTorch 1.13 + CUDA 11.7, one NVIDIA A100-40GB (a 24GB
card is sufficient for every configuration in the paper). Total compute for the
full grid is roughly 60 GPU-hours.

### 3.2 Data

`download_data.sh` fetches ImageNet-1k and CIFAR-10 into `$DATA_ROOT`. Set
`DATA_ROOT` in `config.py` (or via the environment) before running anything. The
`val` split of ImageNet-1k is used both for the few-shot pool (`k=200`) and for
evaluation; targets are never seen during training.

### 3.3 Drivers

| Experiment | Driver | Results dir | Approx. cost |
|---|---|---|---|
| ImageNet main grid (9 methods × 3 budgets) | `run_fewshot_sota.py` | `results_fewshot_sota/` | 25 GPU-h |
| clip-down counterfactual | `run_clipdown.py` | `results_clipdown/` | 9 GPU-h |
| Supplementary sweeps (`k`, `B`, `eps_w`, `L2`) | `run_supplementary.py` | `results_suppl/` | 8 GPU-h |
| CIFAR-10 control | `run_cifar_control.py` | `results_cifar_control/` | 4 GPU-h |
| Zero-optimization (SVD) baseline | `run_singular_vector.py` | `results_svduap/` | 2 GPU-h |
| Cross-architecture (ViT) grid | `run_fewshot_reuse.py --out_dir results_fewshot_vit` | `results_fewshot_vit/` | 12 GPU-h |
| Modern targets (ConvNeXt/Swin/EfficientNet) | `run_p2_targets.py` | `results_p2/` | 3 GPU-h |

Each driver takes `--surrogate` and `--seed` and writes one JSON. The paper uses
surrogates `resnet50, resnet101, vit_b_16` and seeds `42, 1342, 2342`; splits are
fixed (`seed=100` for the few-shot pool, evaluation seed `42`) so that runs are
comparable across surrogates. Because only initialisation varies across the three
seeds, seed-to-seed spread is small; the dominant source of variance is the
surrogate architecture, which is why all claims in the paper are stated over the
surrogate grid rather than over seeds.

Pretrained ImageNet checkpoints are the standard `torchvision` weights; nothing
needs to be downloaded beyond what `torchvision` caches on first use. Where the
paper uses a non-standard initialisation, the protocol is in the appendix and is
implemented in `pretrain_models.py`.

### 3.4 Cluster

The `slurm_*.sh` scripts are the exact submission wrappers used for the reported
runs. They assume a SLURM cluster with a `gpu` partition and one GPU per job; the
only site-specific setting is `DATA_ROOT` in `config.py`.

## 4. Determinism notes

* Each JSON records `config`, so any aggregate can be traced to the exact settings.
* Tables are byte-identical across machines given the same JSON (pure `numpy`
  arithmetic, no floating-point-order-dependent reductions).
* `make_tables.py` rounds only at print time; aggregates are computed at full
  precision. A paired difference quoted in the text can therefore differ from the
  difference of two displayed cells by up to 0.1 pp.
